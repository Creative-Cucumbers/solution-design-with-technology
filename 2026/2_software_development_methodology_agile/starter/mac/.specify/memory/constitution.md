# グループワーク用タイマー Constitution

この演習プロジェクトの「憲法」です。仕様書（spec.md）や計画（plan.md）を作るとき、AIはこの原則に従います。

## Core Principles

### I. ブラウザだけで動く（NON-NEGOTIABLE）

成果物は `index.html` を開くだけで動くこと。サーバーの起動、ビルド、パッケージのインストールを必要としない。
外部CDNへの依存も原則なしとし、必要な場合は1つまでに限る。

### II. 受け入れ条件がすべて

「完成」の判断は、仕様書に書かれた受け入れ条件を満たしているかどうかだけで行う。
受け入れ条件に書かれていない機能は、勝手に足さない。良さそうに見えても足さない。

### III. 保存しない

データはブラウザを閉じたら消えてよい。ログイン、データベース、外部サービスとの連携は作らない。

### IV. 小さく作る

1つのタスクは「動作を目で確認できる単位」まで小さく分ける。
大きな変更を一度に行わず、1機能ずつ実装して確認する。

### V. 日本語で書く

仕様書・計画・タスク・画面の文言は日本語で書く。コード中の識別子は英語でよい。

## 技術的な制約

- 使う技術: HTML / CSS / JavaScript（素のままでよい）
- 対象ブラウザ: 最新の Chrome / Edge / Safari
- テストの自動化は必須としない（受け入れ条件を人が目で確認する）
- ファイル数は必要最小限にする（`index.html` 1ファイルでも構わない）

## 開発ワークフロー

1. 受け入れ条件を人間が書く
2. `/speckit-specify` で仕様書を作り、**人間がレビューして直す**
3. `/speckit-plan` → `/speckit-tasks` で計画とタスクに落とす
4. `/speckit-implement` で実装する
5. 受け入れ条件を1つずつ確認する

AIが出した仕様・計画・タスクは、人間が承認するまで次の段階に進まない。

## Governance

この憲法は、演習の目的（仕様駆動開発を体験する）を優先して定めている。
変更する場合は、なぜ変更するのかを仕様書に記録すること。
