# 演習D-1 / D-2: 学内の落とし物掲示板

## お題

落とし物を拾った人が投稿して、失くした人が探せる掲示板を作ります。

## 受け入れ条件

| | 条件 | 確認の仕方 |
| --- | --- | --- |
| AC1 | 落とし物を**投稿できる**（品名・拾った場所・拾った日） | 3項目を入れて追加すると、画面に出る |
| AC2 | 投稿された落とし物を**一覧で見られる** | 複数件入れると、全部並ぶ |
| AC3 | 投稿を**削除できる** | 消したものが一覧から消える |

## 追加の要望（5節で入れる。先に読まないこと）

| | 要望 | お客さんの言葉 |
| --- | --- | --- |
| 追加1 | **写真を複数枚つけたい** | 「1つの落とし物に、いろんな角度の写真を何枚か載せたい」 |
| 追加2 | **受け取りの履歴を残したい** | 「誰がいつ受け取ったか、過去の分も全部残しておきたい」 |
| 追加3 | **絞り込んだ結果を共有したい** | 「場所と期間で絞り込んで、その画面のURLを友達に送りたい」 |

## 制約

- **ブラウザだけで動くこと。** サーバーの起動、インストール、ネット接続は不要
- 保存は不要。リロードで消えてよい
- ログイン、外部サービス、外部ライブラリは使わない

## 演習D-1（10分）: まず、作ってみる

準備（README 1.4〜1.8）が終わっていることを確認してから始めます。

- `ソフトウェア開発演習/第4回` フォルダを作った
- 自分のOSのZIPをダウンロードして、`第4回` の中で展開した
  - Windows: [starter-windows.zip](https://raw.githubusercontent.com/Creative-Cucumbers/solution-design-with-technology/main/2026/2_software_development_methodology_agile/starter-windows.zip)
  - Mac / Linux: [starter-mac.zip](https://raw.githubusercontent.com/Creative-Cucumbers/solution-design-with-technology/main/2026/2_software_development_methodology_agile/starter-mac.zip)
- Antigravity IDE で `starter-windows`（Macは `starter-mac`）**そのもの**を開いた
- チャットで `/speckit-` と打つと、コマンドが出る

### ① 仕様を作る

```
/speckit-specify 学内の落とし物掲示板を作ります。

受け入れ条件:
1. 落とし物を投稿できる（品名・拾った場所・拾った日を入力する）
2. 投稿された落とし物を一覧で見られる
3. 投稿を削除できる

制約:
- ブラウザだけで動くこと（サーバー・インストール・ネット接続は不要）
- データの保存は不要。リロードで消えてよい
- 外部ライブラリは使わない
```

### ② 計画を作る（**読まずに進む**）

```
/speckit-plan
```

> [!IMPORTANT]
> 出てきた計画は**読まずに**次へ進んでください。今日はこれが実験の条件です。

### ③ タスクに分けて、作る

```
/speckit-tasks
```

```
/speckit-implement
```

### ④ 動かして、データを3件入れる

```
作成した落とし物掲示板をブラウザで開いてください
```

AC1〜AC3を自分で確かめたら、**落とし物を3件、登録してください。**

> [!IMPORTANT]
> **この3件は、5節のチェックAで使います。** 画面を閉じないでください。

## 5節: 追加の要望を入れたあとの、3つのチェック

要望3つを入れたら（4分）、**必ずこの3つを確かめます**（3分）。

**チェックA: さっき入れた3件は、まだ残っているか**

ページを開き直して、④で入れた3件を見る。消えた・崩れた・エラーになった → **データの形が作り直された**ということ。

**チェックB: AC1〜AC3は、まだ全部通るか**

投稿・一覧・削除を、もう一度ひととおり触る。**動いていたものが動かなくなっていないか**を見る。

**チェックC: AIは、何を書き換えたのか**

```
いま追加した3つの要望について、報告だけしてください。コードは変更しないでください。

1. 書き換えたファイルと、おおよその行数
2. 落とし物のデータの形は、変更前と変更後でどう変わりましたか（前 → 後の形で）
3. その新しいデータの形は、誰が決めましたか
4. 最初の受け入れ条件（投稿・一覧・削除）は、いまも全部通りますか
```

**最後に、AIに聞かずに答える質問**

> 「写真は1件につき3枚までにしてください」と言われたら、**どのファイルの、どこを直せばいいですか?**

## 演習D-2（20分）: 設計してから、作り直す

**設計は、ひとりで考え込みません。AIに質問と案を出させて、自分が決めます。**

| | やること | プロンプト / 操作 | 時間 |
| --- | --- | --- | --- |
| 1 | AIに**「何を決めればいいか」を質問させる** | 下の①「決めることを聞くプロンプト」 | 2分 |
| 2 | **データの持ち方を3案**出させて、1つ選ぶ | 下の②「案を3つ出させるプロンプト」 | 3分 |
| 3 | AIに **`design.md` の下書き**を作らせる | 下の③「下書きを作らせるプロンプト」 | 2分 |
| 4 | 下書きを**自分で仕上げる** | [design-template.md](./design-template.md) の「仕上げの3点」 | 3分 |
| 5 | 図を1枚描く | `architecture.drawio.svg` を作る | 2分 |
| 6 | `plan.md` を作らせて、**読む** | 下の④「設計させるプロンプト」 | 3分 |
| 7 | 実装する | `/speckit-tasks` → `/speckit-implement` | 3分 |
| 8 | 追加の要望3つを、もう一度入れて**3つのチェック**をやる | エージェントに依頼 | 2分 |

> [!IMPORTANT]
> **どのプロンプトにも「実装はまだしないでください」を入れてください。** これがないと、AIはすぐ作り始めます。

### ① 決めることを聞くプロンプト

```
これから設計をします。実装はまだしないでください。

学内の落とし物掲示板について、私がいま決めておかないと、
あとで作り直しになることを、質問の形で挙げてください。重要な順に5つまで。
それぞれ、なぜ先に決める必要があるのかを1行で添えてください。
```

### ② 案を3つ出させるプロンプト

```
データの持ち方を3案出して、長所と短所を比べてください。実装はまだしないでください。

次の変更が、あとから必ず来る前提でお願いします。
- 写真を複数枚つけたい
- 受け取りの履歴を残したい（誰がいつ受け取ったか、過去の分も）
- 場所と期間で絞り込んだ結果を、URLで共有したい

それぞれの案について「この変更が来たとき、どこを直すことになるか」も書いてください。
表で比べられる形にしてください。
```

迷ったら、そのまま聞いてください。**「どれがいいですか? 理由も教えてください」**

### ③ 下書きを作らせるプロンプト

```
2案目で行きます。design.md の下書きを作ってください。実装はまだしないでください。

次の3つの見出しだけで、短く書いてください。
1. データの形
2. 画面の責務（どの画面が何を持ち、何を持たないか）
3. 呼び出し方（関数名と、渡すもの・返すもの）

私が決めたこととして、断定で書いてください。
私が決めるべきなのに情報が足りない箇所は、「要確認」と印をつけて、
何を決めればいいかを質問にしてください。
```

### ④ 設計させるプロンプト

```
/speckit-plan design.md に書いたつなぎ目に従って設計してください。
データの形・画面の責務・呼び出し方は、design.md のとおりにしてください。
勝手に変えないでください。変えたほうがよい場合は、理由を書いて提案だけしてください。
```

### 説明できない行が残っているとき

```
design.md の次の行の意味が分かりません。初めて聞く人に説明するつもりで、
短く言い換えてください。なぜそう決めるのがよいのかも1行で教えてください。

（分からない行を貼る）
```

## 演習F（4限）: チームでやること

| | やること | 時間 |
| --- | --- | --- |
| F-1 | ベースの設計を1つ選ぶ → **契約**にする → **ファイル単位で分担** → DoDと統合役を決める | 18分 |
| F-2 | 各自が**自分のファイルだけ**作る（11分）→ **途中で集める**（3分）→ ズレを直す（6分） | 20分 |
| F-3 | 統合して動かす → 受け入れ条件を全員で通す → 振り返りメモ | 12分 |

チーム用のひな形（契約・分担表・DoD）は [design-template.md](./design-template.md) の後半にあります。

### 自分のファイルだけ作らせるプロンプト

```
チームの design.md と、下の契約に従って、list.js だけを作ってください。
他のファイルは作らないでください。変更もしないでください。

契約に書いてある関数名・引数・データの形は、変えないでください。
契約で足りない情報があったら、作る前に私に質問してください。

（ここに契約のコメントを貼る）
```

> [!WARNING]
> **「○○だけ」「他は触らない」の2つを必ず入れてください。** 入れないと、AIはアプリ全部を作り直します。

### チームのルール（3つだけ）

1. **契約を1人で勝手に変えない。** 変えたいときは、チームに言ってから変える
2. **同じファイルを2人で触らない**
3. **ズレたら、契約から外れたほうが直す**（契約が間違っていたら、全員で直す）
